1. Executive Summary
This Business Requirements Document (BRD) provides comprehensive specifications for developing a Converged Risk Assessment Framework (CRAF) demonstration prototype for a banking client. The prototype showcases a custom governance solution designed to address Reserve Bank of India (RBI) regulatory compliance mandates while delivering significant cost savings compared to traditional Governance, Risk & Compliance (GRC) platforms.
1.1 Project Purpose
The primary objective is to win a new client contract by demonstrating a cost-effective, feature-rich governance framework that meets all RBI regulatory requirements. The demo targets C-Suite executives and will be delivered as a 15-20 minute live demonstration showcasing a fully functional working prototype.
1.2 Business Problem
Indian banks and Non-Banking Financial Companies (NBFCs) are facing critical challenges:
RBI has mandated implementation of comprehensive governance frameworks
Current market solutions (SAP GRC, SAS GCM, RSA Archer) require investments running into crores
Many financial institutions lack complete or adequate governance frameworks
Manual compliance and risk assessment processes are time-consuming, error-prone, and resource-intensive
Increasing regulatory compliance pressure with frequent RBI circulars and guideline updates
Fragmented view of risk across compliance and financial reporting domains
1.3 Solution Overview
The Converged Risk Assessment Framework is a custom-built solution that integrates Compliance Risk and Financial Reporting Risk management into a unified platform. Key capabilities include:
Automated Inherent Risk Assessment based on parametric scoring (Likelihood × Impact)
Comprehensive Control Quality Assessment evaluating design effectiveness
Control Performance Assessment tracking monitoring and testing results
Automated Residual Risk calculation with drill-down from enterprise to obligation level
Executive dashboards with real-time and periodic assessment capabilities
Early warning indicators for proactive risk management
Coverage of 30+ Assessment Units across all business areas
Emphasis on RBI regulatory requirements and compliance obligations

7. Database Schema
This section defines the database structure for the CRAF system.
7.1 Table Definitions
Assessment Units Table:
CREATE TABLE assessment_units (
  au_id INT PRIMARY KEY AUTO_INCREMENT,
  au_code VARCHAR(50) UNIQUE NOT NULL,
  au_name VARCHAR(200) NOT NULL,
  theme_id INT NOT NULL,
  business_area VARCHAR(100),
  owner_name VARCHAR(100),
  description TEXT,
  is_active BOOLEAN DEFAULT TRUE,
  created_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (theme_id) REFERENCES themes(theme_id)
);

Themes Table:
CREATE TABLE themes (
  theme_id INT PRIMARY KEY AUTO_INCREMENT,
  theme_code VARCHAR(50) UNIQUE NOT NULL,
  theme_name VARCHAR(100) NOT NULL,
  description TEXT
);

Compliance Obligations Table:
CREATE TABLE compliance_obligations (
  obligation_id INT PRIMARY KEY AUTO_INCREMENT,
  obligation_code VARCHAR(50) UNIQUE NOT NULL,
  regulation_source VARCHAR(200),  -- e.g., 'RBI Master Direction on...'
  regulation_ref VARCHAR(100),     -- e.g., 'RBI/2023-24/05'
  obligation_desc TEXT NOT NULL,
  frequency VARCHAR(50),            -- Daily, Weekly, Monthly, etc.
  au_id INT NOT NULL,
  criticality VARCHAR(50),          -- Critical, High, Medium, Low
  is_active BOOLEAN DEFAULT TRUE,
  FOREIGN KEY (au_id) REFERENCES assessment_units(au_id)
);

Controls Table:
CREATE TABLE controls (
  control_id INT PRIMARY KEY AUTO_INCREMENT,
  control_code VARCHAR(50) UNIQUE NOT NULL,
  control_name VARCHAR(200) NOT NULL,
  control_desc TEXT,
  obligation_id INT NOT NULL,
  control_type VARCHAR(50),         -- Preventive, Detective
  control_nature VARCHAR(50),        -- Manual, IT-driven, IT-based manual
  control_frequency VARCHAR(50),
  monitoring_mechanism VARCHAR(100), -- Maker-checker, automated, etc.
  is_documented BOOLEAN,
  owner_role VARCHAR(100),
  is_active BOOLEAN DEFAULT TRUE,
  FOREIGN KEY (obligation_id) REFERENCES compliance_obligations(obligation_id)
);

Inherent Risk Assessment Table:
CREATE TABLE inherent_risk (
  ir_id INT PRIMARY KEY AUTO_INCREMENT,
  au_id INT NOT NULL,
  assessment_period_id INT NOT NULL,
  -- Likelihood Parameters
  volume_growth_score INT,
  complexity_score INT,
  regulatory_returns_score INT,
  compliance_breaches_score INT,
  control_failures_score INT,
  customer_complaints_score INT,
  likelihood_score INT NOT NULL,   -- Calculated average, scaled
  likelihood_rating VARCHAR(50),    -- Rare, Unlikely, Possible, Likely, Almost Certain
  -- Impact Parameters
  business_impact_score INT,
  reputational_impact_score INT,
  financial_penalty_score INT,
  gl_impact_score INT,
  impact_score INT NOT NULL,       -- Calculated weighted average
  impact_rating VARCHAR(50),
  -- Inherent Risk Calculation
  inherent_risk_score INT NOT NULL, -- Likelihood * Impact
  inherent_risk_rating VARCHAR(50), -- Extremely High, Very High, High, Minor, Insignificant
  assessment_date DATE,
  FOREIGN KEY (au_id) REFERENCES assessment_units(au_id),
  FOREIGN KEY (assessment_period_id) REFERENCES assessment_periods(period_id)
);

Control Quality Assessment Table:
CREATE TABLE control_quality (
  cq_id INT PRIMARY KEY AUTO_INCREMENT,
  control_id INT NOT NULL,
  assessment_period_id INT NOT NULL,
  -- Design Parameters
  monitoring_score INT,            -- 1, 3, or 5
  automation_score INT,            -- 1, 3, or 5
  control_type_score INT,          -- 1, 3, or 5
  documentation_score INT,         -- 1 or 5
  cqa_raw_score INT,               -- Product of 4 parameters
  cqa_scaled_score INT,            -- Scaled to 5/10/15/20/25
  control_category VARCHAR(100),   -- Significantly Effective, Effective, etc.
  FOREIGN KEY (control_id) REFERENCES controls(control_id),
  FOREIGN KEY (assessment_period_id) REFERENCES assessment_periods(period_id)
);

Control Performance Assessment Table:
CREATE TABLE control_performance (
  cp_id INT PRIMARY KEY AUTO_INCREMENT,
  control_id INT NOT NULL,
  assessment_period_id INT NOT NULL,
  kci_linked BOOLEAN,
  kci_result VARCHAR(50),          -- Pass, Fail, NA
  self_assessment_result VARCHAR(50), -- Pass, Pass with Exception, Fail, NA
  control_testing_result VARCHAR(50),  -- Pass, Pass with Exception, Fail, Not Tested
  cpa_score INT,                   -- Combined score from KCI & testing
  cpa_scaled_score INT,            -- Scaled to 5/10/15/20/25
  performance_category VARCHAR(100),
  FOREIGN KEY (control_id) REFERENCES controls(control_id),
  FOREIGN KEY (assessment_period_id) REFERENCES assessment_periods(period_id)
);

Control Environment Rating Table:
CREATE TABLE control_environment_rating (
  cer_id INT PRIMARY KEY AUTO_INCREMENT,
  au_id INT NOT NULL,
  assessment_period_id INT NOT NULL,
  cqi_score DECIMAL(5,2),          -- Control Quality Index
  cpi_score DECIMAL(5,2),          -- Control Performance Index
  cer_score DECIMAL(5,2),          -- CQI * CPI
  cer_rating VARCHAR(100),         -- Effective, Meets Requirements, etc.
  FOREIGN KEY (au_id) REFERENCES assessment_units(au_id),
  FOREIGN KEY (assessment_period_id) REFERENCES assessment_periods(period_id)
);

Residual Risk Table:
CREATE TABLE residual_risk (
  rr_id INT PRIMARY KEY AUTO_INCREMENT,
  au_id INT NOT NULL,
  assessment_period_id INT NOT NULL,
  inherent_risk_score INT NOT NULL,
  cer_score DECIMAL(5,2) NOT NULL,
  residual_risk_score DECIMAL(5,2), -- IR / CER
  residual_risk_rating VARCHAR(50), -- Well Controlled, Meets Requirement, etc.
  aggregate_weight DECIMAL(5,2),
  assessment_date DATE,
  FOREIGN KEY (au_id) REFERENCES assessment_units(au_id),
  FOREIGN KEY (assessment_period_id) REFERENCES assessment_periods(period_id)
);

9. User Stories & Use Cases
This section details the three priority business scenarios to be demonstrated.
9.1 Scenario 1: Audit Finding Remediation
User Story:
As a Head of Compliance, I want to track and remediate audit findings systematically so that we can reduce residual risk and demonstrate control improvements to auditors.

Background:
Internal Audit has identified a control deficiency in the Trade Finance AU
The finding indicates inadequate maker-checker controls for LC issuance
Audit rating: Needs Improvement
Required remediation within 90 days

Demo Flow:
Start at Executive Dashboard showing Trade Finance AU with High residual risk (red indicator)
Drill down to Trade Finance AU detail view
Show Inherent Risk assessment (score: 300, rating: Very High)
Display Control Environment section with low CQI score (40%) due to control deficiency
Navigate to specific obligation: 'RBI Master Direction on Trade Finance - LC Issuance'
Show the deficient control with low quality rating (Significant Improvement Needed)
Switch to 'Before/After' comparison view
Demonstrate the control improvement plan:
Before: Manual process, no maker-checker (Control Quality score: 1)
After: Automated maker-checker implemented (Control Quality score: 25)
Show impact on metrics:
CQI improved from 40% to 75%
Residual Risk reduced from 300 to 120 (High to Minor)
AU status changed from Red to Yellow
Display audit trail showing remediation steps and timeline
Show early warning indicator no longer flagging this AU

Acceptance Criteria:
User can drill down from Enterprise → Trade Finance AU → LC Obligation → specific control
Before/After comparison clearly shows improvement in control quality and residual risk
All calculations automatically update based on control enhancement
Visual indicators (colors) change appropriately with risk reduction
9.2 Scenario 2: Control Failure Investigation
User Story:
As a Head of Operational Risk, I need to investigate control failures to identify root causes and prevent recurrence across similar controls bank-wide.

Background:
KCI monitoring has flagged a control failure in Retail Liabilities AU
The failed control: Daily reconciliation of cash balances
3 failures in past month, triggering early warning indicator
Need to investigate and remediate immediately

Demo Flow:
Executive Dashboard shows early warning indicator for Retail Liabilities
Click on early warning alert icon
System highlights Retail Liabilities AU with deteriorating trend (amber alert)
Drill to Retail Liabilities AU detail view
Navigate to Controls section, filter by 'Recent Failures'
Select failed control: 'Daily Cash Reconciliation'
Show Control Performance Assessment:
